# 架构文档统一模板规范 — ARCH-TEMPLATE

> 本文档定义 docs/ 及 docs/architecture/ 下所有 Markdown 架构文档的统一结构规范。
> 目的：统一标题层级、元信息字段、章节结构，使文档可扫描、可检索、可维护。
> 硬约束：重构只动结构/格式/排版，实质内容一字不改；ROADMAP.md 为项目唯一真理文档，不适用本模板。

---

## 一、标题层级约定

| 层级 | 标记 | 用途 | 命名规范 |
| --- | --- | --- | --- |
| H1 | `# ` | 文档标题 | `主题 + 破折号 + 副标题`，如 `# PAA 架构设计 v2 — 以能力支柱为中心` |
| H2 | `## ` | 章节标题 | 中文序号（`一、二、三…`）或阿拉伯数字（`1. 2. 3.`），如 `## 一、总体架构` |
| H3 | `### ` | 小节标题 | `X.Y` 编号（`1.1 设计原则`）或纯描述性（`### 已验证`） |

规则：
- 全文只允许一个 H1，位于文件首行，作为文档唯一标题。
- H2 为顶层章节，H3 为 H2 下的小节，不得跳级（不允许 H2 直接跳到 H4）。
- 同级标题用词风格保持一致（要么全部中文序号，要么全部阿拉伯数字，同文档内不混用）。

---

## 二、元信息字段（H1 下方）

H1 下方紧跟元信息区块，格式为块引用（`>`）加粗字段：

```
# 文档标题 — 副标题

> **作者**：xxx
> **版本**：v1.0
> **日期**：YYYY-MM-DD
> **状态**：草案 / 评审中 / 已定稿
> **关联文档**：指向相关文档的相对链接
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 作者 | 选填 | 文档维护者 |
| 版本 | 选填 | 语义化版本号 |
| 日期 | 选填 | 最后更新日期 |
| 状态 | 选填 | 文档成熟度 |
| 关联文档 | 选填 | 相关文档链接（相对路径） |

若原文无元信息，重构时不新增（避免杜撰内容）；若原文已有类似信息，统一收敛到上述字段格式。

---

## 三、章节结构约定

推荐章节顺序（可按文档实际内容增删，但顺序保持逻辑递进）：

1. **背景 / 概述**：文档要解决的问题、适用场景、读者对象。
2. **设计 / 方案**：核心内容，含设计原则、架构图描述、模块划分。
3. **实现细节**：关键路径、数据结构、接口约定（如适用）。
4. **边界 / 约束**：已知限制、不适用范围、依赖前提。
5. **演进 / 路线**：未来方向、待办项（如适用）。
6. **附录**：术语表、参考链接、变更记录（如适用）。

约定：
- 章节用 H2，小节用 H3，正文用普通段落、列表、表格。
- 表格统一用 Markdown 管道表格（`| 列1 | 列2 |`），表头加分隔行。
- 代码块标注语言（如 ```ts、```json）。
- 不改变原文实质内容，仅调整其呈现层级与顺序。

---

## 四、适用范围

- **适用**：docs/ 根目录及 docs/architecture/ 下的 Markdown 架构文档。
- **不适用**：
  - `ROADMAP.md`（项目唯一真理文档，禁止改动其内容结构）。
  - 非 Markdown 文件（如 .html）。
  - 日志/记忆类文件（DEVLOG.md 等可参照但非强制）。

---

## 五、重构操作纪律

1. 只动结构、格式、排版；实质内容一字不改。
2. 每改完一个文档，立即用 fs_read 读回验证修改已在磁盘生效。
3. 不确定是否该保留的内容，保持原样，不擅自增删。
4. 标题层级、章节顺序改动前，先通读原文确认语义归属。
