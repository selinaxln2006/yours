# PAA A4 re-plan 冒烟测试

> 冒烟目标：验证 PAA 的 A4 re-plan 功能（子任务失败后 LLM 重规划未完成部分，增删改后继续）。

## 一、A4 re-plan 功能总结

**核心机制**：子任务失败后，由 LLM 对**未完成部分**进行重规划（re-plan），对剩余任务树做**增删改**，更新落盘，然后**继续执行**——不卡死、不自爆、不硬冲。

失败判定触发 replan 的三种信号：
- `toolFail`（工具调用失败）
- `toolCalls > 30%`（工具调用失败率过高）
- 无产出 / 验证失败

## 二、设计要点（来自 ROADMAP.md A4 章节）

| 维度 | 设计 |
|------|------|
| 落点 | planner 内钩子 + 新增 replan 轮 |
| 触发条件 | 子任务失败判定（toolFail / toolCalls > 30% / 无产出 / 验证失败） |
| 流程 | LLM 读失败原因 → 增删改剩余任务树 → 更新 task-tree.json → 继续 |
| 依赖 | ① Task Decomposition（planner 调度层）+ ③ 断点续跑（任务树落盘） |
| 能力定位 | 中途失败不自爆，自主调整计划 |
| 配套 | ⑤ 并行工具（同轮无依赖 toolCalls 并行） |

**关键洞察**：A4 是挂在 ① planner 调度层上的钩子，做 ① 即同时激活 ③ ④ 的骨架；任务树落盘（断点续跑）直接支撑 replan 的"增删改剩余任务树"。
