## 0. 总则：三条禁令（违反任何一条 = 立即停止）

| # | 禁令 | 定义 | 违反而非例外 |
|---|---|---|---|
| B1 | **不静默造轮子** | 任何部件实现前，必须先给对标表（X.1），说明"取谁的精华、为什么" | 直接开写 = 违规 |

## 2. 每个 Phase 的四道审核点：X.1 → X.2 → X.3 → X.4

```
X.1 设计讲解 ⛔ 未确认，不写一行代码
  · 产出：本 Phase 对标表 —— 每个部件：取谁的精华 / 不取什么 / 为什么 / 我们的版本
  · 第一行固定写：用的什么：[X]｜没用你给的什么：[Y]｜原因：[Z]
  · 俪宁回复"过"或"改"。没过 = 不得进入 X.2

X.2 实现
  · 每完成一个文件或每 30 分钟，向俪宁报一次进度（B3）
  · DEVLOG 同步写"设计决策：为什么 A 不选 B（参考：X 的 Y）"
  · 任何写操作先列清单，等确认

X.3 联测 ⛔
  · 俪宁用真实任务实测，验收标准 = G1–G7 对应项（见 §4）
  · 实测不过 = 回到 X.2，不得进入 X.4

X.4 收尾 ⛔
  · DEVLOG 反思（做了什么/没做什么/下次改进）
  · git commit（信息含 Phase 号）
  · 记忆固化（写 .workbuddy/memory）
  · 向俪宁汇报四件套：做了什么 / 没做什么 / 下一步 / 待确认项
```

## 5. 合规基线（已核实的本地许可证）

| 框架 | 许可证 | 边界 |
|---|---|---|
| deepseek-harness (DSH) | **MIT**（本地已读 LICENSE） | 可自由 import，义务=保留版权声明 |
| Operit | **LGPL-3.0**（本地已读 LICENSE） | 只取设计思想，零代码复制；动态链接合法 |
| TencentDB Agent Memory | **MIT**（公开信息） | 可借鉴分层记忆思想；精确结论以 repo LICENSE 为准 |
| code-memory | 待确认 repo 位置 | 未定位本地文件，结论待补 |
| MCP | 开放标准协议 | 直接用 |

**合规三原则**：① MIT 框架按依赖引用（天然合规）② LGPL 只取思想不抄代码 ③ README/DEVLOG 诚实标注"架构自研，设计参考 DSH(MIT)/Operit(LGPL)/TencentDB(MIT) 思想"。不声称 100% 从零原创，不把开源代码改名当自己的。

**主体性试金石**：架构图里谁在最上面、谁定义循环/状态/格式，谁就是主体。PAA 的代码里若出现"import 开源 core 决定循环"= 被殖民，立即回退。

## 8. P0 X.1 设计讲解（2026-08-24 交付，⛔ 待俪宁确认）

用的什么：PAA 按 v2 设计文档自研（循环/状态/格式全部自研）｜没用你给的什么：没有 import 任何开源 harness 的 core 决定 PAA 行为｜原因：PAA 主体性红线（v2 原文"技能包格式自研…兼容别人=交出设计主权"）

### 8.1 P0 范围（v2 已定义）

P0 = 骨架四件套：**AgentLoop + LLMAdapter + ToolPipeline + SessionMgr**（+ 权限模型初版，因 AgentLoop 依赖）

### 8.2 对标表

| PAA 部件 | 取谁的精华 | 为什么取 | 不取什么 / 为什么 | 我们的版本 |
|---|---|---|---|---|
| **AgentLoop**（循环结构） | DSH 的 Turn/Step 分层 + ReactLoopAgent 迭代思想 | 分层让"一轮=多个步骤"可观测、可中断，是成熟 agent 循环的通用解法；迭代式重试比单次调用稳 | 不 import DSH core——循环是我们的，import 即殖民（B2） | AgentLoop：round/step 两层；每 round 记忆检索注入；abort/inject/maxRounds 控制（v2 已定义） |
| **LLMAdapter** | Operit 20+ provider 适配模式（统一接口隔离各家差异） | 同一接口换底座，避免 provider 锁死；v0.6 已验证 OpenAI 兼容 + Anthropic 双协议 | 不抄 Operit 实现代码（LGPL）；只取"接口分层"设计思想 | 自研 adapter：`LLMAdapter` 接口 + provider 实现（OpenAI 兼容 / Anthropic），config 驱动 |
| **ToolPipeline**（工具流转） | DSH 的 waterfall 工具管道 + Operit AIToolHandler Hook 思想 | 顺序管道保证工具结果可追踪、可审计；Hook 让权限/日志插在每步前后 | 不 import 两者的管道实现 | 自研 pipeline：工具注册 → 参数校验 → 执行 → 结果回写上下文（v2 架构图） |
| **SessionMgr** | DSH session 事件溯源思想（全量操作可回放） | 事件溯源让会话可审计、可恢复，是工程级会话的标准做法 | 存储格式自研——会话数据主权（不存 DSH 格式） | 自研：session 事件流（user/assistant/tool/error），JSON 落盘，可回放 |
| **权限模型**（初版） | Operit 三级权限 + DSH guard 思想 | 写操作必须分级确认，防 agent 越权 | 不用 Operit 实现，权限表格式是 v2 的 | v2 权限表：ALLOW / ASK / 永远确认不可降级 + 工具 risk 分级 + L0-L4 Autonomy |
| **沙箱/进程** | DSH sandbox / subprocess | 命令隔离是安全底线，OS 原语不值得自研 | 只当底层库按需引用 | 换掉不影响架构图（零件位） |
| **记忆（P1 预研）** | TencentDB Agent Memory 四资产分层（Chat/Skill/Wiki/CodeGraph）+ DSH spill 压缩思想 | 分层是"记忆≠流水账"的关键：对话/技能/知识/代码分仓，检索才准 | 数据模型 + import/export 格式自研（**记忆主权红线**，不用 TencentDB/DSH 格式） | memories[]：fact / preference / episodic / skill-note 四类 + 文件即记忆 + memory__search |
| **技能包（P3 预研）** | Operit ToolPkg JSON+JS 声明思路 | 声明式技能包可分发、可下载（G5 需要） | 不兼容 Operit 生态（v2 红线：兼容别人=交出主权） | 自研 ToolPkg 格式（schema 自定） |
| **外部工具** | MCP 标准协议 | 协议是标准，不是框架 | — | 直接用 MCP 客户端 |

### 8.3 P0 验收映射（X.3 实测项）

- G1 读：agent 用 fs 工具定位文件（grep+切片读）
- G2 写：agent 用 write/patch 精确修改文件
- G3 自诊断：同一任务"定位→读→改→验证"完整闭环，无人工介入
- 权限：写操作默认 ASK，俪宁确认才执行；审计日志完整
